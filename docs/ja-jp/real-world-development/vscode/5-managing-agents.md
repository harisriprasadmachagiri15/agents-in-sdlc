Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、作業は開発者のマシン上でリアルタイムに実行されます。ツールの呼び出しやファイルの編集を順に確認できます。差分をインラインでレビューし、変更を個別に採用または却下し、エディターを離れずに追加のプロンプトで会話を調整できます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッション中にエージェントへ指示し、ハイコントラストモードとともにライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中に、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は、差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャット内に表示されます。
    - 変更を採用するには **Keep** を選択します。
    - 変更を取り消し、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、セッション中に変更されたすべてのファイルを確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは処理を一時停止し、**Allow** を表示します。内容を確認し、実行を許可するコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードが実装されたら、同じ会話でライトモードの切り替えも追加します。会話を続けることで、エージェントは前の作業で変更したコンポーネント、スタイルの方法、local storage を使った設定の保持方法を引き継げます。ライトモードの切り替えは、ハイコントラストの切り替えと同じユーザーインターフェイス (UI) 領域に追加します。

1. Copilot Chat の入力欄に、次のプロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが変更済みのファイルを調べ、ライトモードの追加を提案する様子を確認します。
3. ハイコントラストモードと同様に、追加された編集をレビューし、**Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合 (たとえば、切り替え UI を意図しない方法でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止してから、追加の説明を送信します。

> [!TIP]
> 作業中のセッションに指示を送ると、新しく始めるよりも早く調整できます。追加のプロンプトを使って変更を依頼します (例: 「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使ってください」)、方向を修正します (例: 「切り替え UI をリファクタリングせず、ライトモードを既存の設定パネルに追加してください」)、作業範囲を広げます (例: 「両方の切り替えにキーボードショートカットも追加してください」)。

## 変更されたファイルをレビューする

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティのパターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック ハイパーテキスト マークアップ言語 (HTML)、local storage による設定の保持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中の作業を監視して方向を調整しました。ファイル編集を順にレビューして採用または却下し、会話を続けたまま追加の作業を依頼しました。

このレッスンでは、次の作業を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または却下しました。
- 追加のプロンプトでセッション中の作業を調整しました。

次のレッスンでは、アクセシビリティの変更を pull request として公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
